Build, validate, stop

The agent builds, checks its own work against written rules, lists what it touched and stops. Here's what that check can and can't catch.

1Guess first

The agent has finished a build. The last lines of its reply:

Rewrote 52 files. Validator: 710 checks, 710 PASS. Stopping here.

Does that mean the report opens and looks right in Desktop?

The is the agent's own checklist, run after every build. It's part of the : the tools and checks wrapped around the model so it can act, and be caught.

2Break it on purpose

Break the build on purpose, then run the validator. Catch three faults. One of them it will never catch.

Caught 0 of 3
> not run yet

3Every bug becomes a check

The check count didn't stay at 710. It grew to 1,533. Almost every new check started as a real bug.

Clicking a tile brought it to the front and hid its button. Grouping each tile with its button fixed it. Which check was added?

That's the pattern: you find the problem in Desktop, the fix goes into the build, and a check goes into the validator so the fix sticks.

4The file list

The build ends with a list of every file it rewrote. You expected 52. It lists 60.

PS> git diff -w --stat 52 files changed (the tiles) PS> git diff --stat 60 files changed

Ignoring whitespace, only 52 differ. What are the other 8?

PS> git restore <the 8 layout-only files>
